## What is ktroid?

**ktroid** (alias `ktd`) is a modern, lightweight Command Line Interface (CLI) that brings the power of native Android development to your terminal. It replaces the heavy, resource-intensive Android Studio GUI with fast, scriptable, and modular terminal commands.

Whether you're developing on an underpowered laptop, building in headless environments, or you simply prefer working in Vim/Neovim, `ktroid` provides everything you need. From project generation and dependency management to signing APKs and launching emulators, `ktroid` handles the Android ecosystem effortlessly.

**Note:** The CLI provides two identical commands: `ktroid` and `ktd`. For brevity, all examples in this documentation use the shorter `ktd`.

## Philosophy

- **Terminal-First:** No heavy IDE required. Work where you are most productive.
- **Offline-First:** Projects rely on a local `config.json` for reproducible, offline builds. Internet is only required when fetching SDK updates.
- **No Magic:** `ktroid` does not invent a new build system. It transparently wraps the official Android toolchain (`gradle`, `adb`, `sdkmanager`, `keytool`). Projects generated by `ktroid` are 100% compatible with Android Studio if you ever decide to switch back.

## Who is this for?

**You'll love it if...**
- You use Vim, Neovim, Emacs, or VS Code as your primary editor.
- You develop on low-spec hardware (or battery-constrained environments) where Android Studio is too slow.
- You want to automate Android builds in CI/CD pipelines.
- You prefer the speed and scriptability of a CLI over clicking through GUI menus.

**You probably don't need it if...**
- You rely heavily on Android Studio's visual Layout Editor, Navigation Graph Editor, or memory profilers.
- You are a beginner looking for drag-and-drop UI builders.

## Installation

The primary method to install `ktroid` is via `pip` (once published to PyPI):

```bash
pip install ktroid
```

**From Source:**

```bash
git clone https://github.com/apfsource/ktroid.git
cd ktroid
pip install -e .
```

After installation, both `ktroid` and `ktd` commands are available globally in your terminal. No binary changes, no PATH hacks — it works anywhere Python works.

## First-Time Setup

To get started, simply run the master setup wizard:

```bash
ktd setup
```

The Master Setup Wizard handles the entire Android environment configuration for you:
1. Checks for Java JDK.
2. Downloads and extracts Gradle.
3. Downloads the Android Command Line Tools specific to your OS (Linux, macOS, or Windows).
4. Automates `sdkmanager` to install necessary packages (`platform-tools`, `platforms;android-XX`, `build-tools`).
5. **Auto-Path:** Automatically modifies your `~/.bashrc`, `~/.zshrc`, or Windows Registry (`HKEY_CURRENT_USER\Environment`) to configure `ANDROID_HOME` and system paths.

## Quick Example

Here is a realistic workflow showing how to create, build, and run an app using `ktd`:

```bash
# 1. Create a new project
ktd create AwesomeApp com.mycorp.awesome

# 2. Enter the project directory
cd AwesomeApp

# 3. Add some common dependencies
ktd dep glide
ktd dep room

# 4. Add required permissions
ktd perm internet

# 5. Connect your device or start an emulator
ktd emulator start Pixel_API_35

# 6. Build, install, and run the debug APK in one step
ktd run

# 7. Monitor the app logs
ktd logs
```

## Complete Command Reference

### Project Setup

#### `create`
Create a new Android project.
- **Usage:** `ktd create <project_name> [package_name]`
- **Arguments:**
  - `project_name` (Required): Name of your app.
  - `package_name` (Optional): Application ID (e.g., `com.example.app`).
- **What it does:** Generates a complete Android Studio-compatible project structure with Gradle wrappers, AndroidManifest, and default Kotlin activities.
- **Example:**
  ```bash
  ktd create MyApp com.mycorp.app
  ```

#### `init`
Initialize a project in the current directory.
- **Usage:** `ktd init`
- **Arguments:** None. Prompts interactively.
- **What it does:** Populates the current working directory with an Android project structure. Warns if the directory is not empty.
- **Example:**
  ```bash
  ktd init
  ```

#### `info`
Extract project info from `build.gradle`.
- **Usage:** `ktd info`
- **Arguments:** None.
- **What it does:** Parses the `app/build.gradle` file and prints the Application ID, version codes, and target/min SDKs.
- **Example:**
  ```bash
  ktd info
  ```

### Building & Running

#### `build`
Compile and build the project.
- **Usage:** `ktd build [action]`
- **Arguments:**
  - `action` (Optional, default `debug`): Build type. Valid options are `debug`, `release`, `bundle`.
- **What it does:** Runs `gradlew assembleDebug`, `assembleRelease`, or `bundleRelease`. For release builds, it automatically verifies the APK signature using `apksigner` or `jarsigner`.
- **Example:**
  ```bash
  ktd build release
  ```

#### `lint`
Run Android code quality and linting checks.
- **Usage:** `ktd lint`
- **What it does:** Executes `./gradlew lint` to analyze your project's source code for potential bugs, security issues, optimization, and accessibility problems.
- **Example:**
  ```bash
  ktd lint
  ```

#### `run`
Build, install, and launch the application.
- **Usage:** `ktd run`
- **Arguments:** None.
- **What it does:** Automatically builds the `debug` APK, asks you to select a connected device (if multiple are connected), installs the APK via ADB, and launches the `MainActivity`.
- **Example:**
  ```bash
  ktd run
  ```

#### `clean`
Clean the build directories.
- **Usage:** `ktd clean`
- **Arguments:** None.
- **What it does:** Executes `./gradlew clean` to remove previous build outputs.
- **Example:**
  ```bash
  ktd clean
  ```

#### `signing`
Configure Android signing for release builds.
- **Usage:** `ktd signing`
- **Arguments:** None. Prompts interactively.
- **What it does:** Generates a `signing.properties` file. If you don't have a keystore, it automatically uses `keytool` to generate an RSA 2048-bit release keystore for you.
- **Example:**
  ```bash
  ktd signing
  ```

### Device & Emulator Management

#### `emulator`
Manage Android Virtual Devices (AVDs).
- **Usage:** `ktd emulator <action> [name]`
- **Arguments:**
  - `action` (Required): `list`, `start`, or `create`.
  - `name` (Optional): Name of the emulator to start.
- **What it does:** Wraps `avdmanager` and `emulator` commands. `list` shows available AVDs. `start` boots the emulator in the background. `create` interactively builds a new AVD (and downloads system images if necessary).
- **Example:**
  ```bash
  ktd emulator start Pixel_API_35
  ```

#### `logs`
Smart Logcat viewer.
- **Usage:** `ktd logs`
- **Arguments:** None.
- **What it does:** Reads your `applicationId` from `build.gradle`, finds the running PID on the device, and strictly filters logcat output so you only see your app's logs.
- **Example:**
  ```bash
  ktd logs
  ```

#### `install`
Install a specific APK to a device.
- **Usage:** `ktd install <apk_path>`
- **Arguments:**
  - `apk_path` (Required): Path to the APK file.
- **What it does:** Prompts for device selection (if multiple exist) and uses `adb install` to push the APK to the device.
- **Example:**
  ```bash
  ktd install app/build/outputs/apk/release/app-release.apk
  ```

#### `uninstall`
Uninstall an app from the device.
- **Usage:** `ktd uninstall [package_name]`
- **Arguments:**
  - `package_name` (Optional): Package to remove.
- **What it does:** Uninstalls the application. If no package is provided, it reads the current project's package name from `build.gradle`.
- **Example:**
  ```bash
  ktd uninstall com.mycorp.app
  ```

#### `screen`
Start screen mirroring using scrcpy.
- **Usage:** `ktd screen`
- **What it does:** Connects to your device and starts a screen mirroring session directly on your PC, allowing you to control the device with your mouse and keyboard. *Requires `scrcpy` to be installed on your system.*
- **Example:**
  ```bash
  ktd screen
  ```

#### `connect-wifi`
Connect to an Android device wirelessly via Wi-Fi (Android 11+).
- **Usage:** `ktd connect-wifi <ip_address>`
- **Arguments:**
  - `ip_address`: The IP address (and optional port) of the device. Default port is `5555`.
- **What it does:** Wraps `adb connect`. Useful for deploying and debugging without a USB cable. Requires "Wireless Debugging" to be enabled on the device.
- **Example:**
  ```bash
  ktd connect-wifi 192.168.1.15
  ```

#### `db-pull`
Extract app databases and shared preferences from the device.
- **Usage:** `ktd db-pull [--dest <folder>]`
- **What it does:** Uses `run-as` to safely export your app's sandboxed SQLite databases and XML shared preferences directly to your PC for inspection. Extremely helpful for debugging local storage issues.
- **Example:**
  ```bash
  ktd db-pull --dest my_app_data
  ```

### Dependency Management

#### `dep`
Add a dependency to `build.gradle`.
- **Usage:** `ktd dep <name>`
- **Arguments:**
  - `name` (Optional): Dependency shortcut or full Maven coordinates.
- **What it does:** Automatically injects an `implementation` block into your `app/build.gradle`. Supports shortcuts for common libraries (e.g., `glide`, `retrofit`, `coroutines`, `room`). Leave empty to see the list of shortcuts.
- **Example:**
  ```bash
  ktd dep retrofit
  ktd dep "com.google.code.gson:gson:2.10.1"
  ```

#### `dep-list`
List all current dependencies.
- **Usage:** `ktd dep-list`
- **Arguments:** None.
- **What it does:** Parses and neatly lists all `implementation`, `api`, and test dependencies currently active in the project.
- **Example:**
  ```bash
  ktd dep-list
  ```

#### `dep-remove`
Remove a dependency.
- **Usage:** `ktd dep-remove <dep_name>`
- **Arguments:**
  - `dep_name` (Required): String matching the dependency to remove.
- **What it does:** Safely finds and removes the dependency line from `app/build.gradle`.
- **Example:**
  ```bash
  ktd dep-remove retrofit
  ```

### Permission Management

#### `perm`
Add a permission to `AndroidManifest.xml`.
- **Usage:** `ktd perm <name>`
- **Arguments:**
  - `name` (Optional): Permission shortcut or full string.
- **What it does:** Injects a `<uses-permission>` tag into the manifest. Supports shortcuts like `internet`, `camera`, `location`, `storage`. Leave empty to view shortcuts.
- **Example:**
  ```bash
  ktd perm internet
  ```

#### `perm-remove`
Remove a permission.
- **Usage:** `ktd perm-remove <name>`
- **Arguments:**
  - `name` (Required): Permission string or shortcut.
- **What it does:** Removes the specified permission tag from `AndroidManifest.xml`.
- **Example:**
  ```bash
  ktd perm-remove camera
  ```

### Resources & Assets

#### `logo`
Generate multi-density app icons.
- **Usage:** `ktd logo <path_to_image>`
- **Arguments:**
  - `path_to_image` (Required): Path to your source logo PNG.
- **What it does:** If the `Pillow` Python library is installed, it intelligently resizes your image into `mdpi`, `hdpi`, `xhdpi`, `xxhdpi`, and `xxxhdpi` formats and places them in the `res/mipmap` directories.
- **Example:**
  ```bash
  ktd logo my_design.png
  ```

#### `string-add`
Add a new string resource directly into `strings.xml`.
- **Usage:** `ktd string-add <name> <value> [--locale <code>]`
- **Arguments:**
  - `name`: The resource name (e.g., `app_name`).
  - `value`: The text value.
  - `--locale`: (Optional) The locale folder to target (e.g., `es` for `values-es`).
- **What it does:** Interactively injects a new `<string>` tag into your project's resource files, streamlining the localization process without opening an XML editor.
- **Example:**
  ```bash
  ktd string-add welcome_message "Welcome to Ktroid!"
  ktd string-add welcome_message "¡Bienvenido a Ktroid!" --locale es
  ```

### Testing

#### `test`
Run project tests.
- **Usage:** `ktd test [test_type]`
- **Arguments:**
  - `test_type` (Optional, default `unit`): `unit`, `instrumented`, or `all`.
- **What it does:** Runs `./gradlew test` for local JVM tests, or `connectedAndroidTest` for instrumented tests on an emulator/device.
- **Example:**
  ```bash
  ktd test instrumented
  ```

### Version & Release

#### `bump`
Bump the app version.
- **Usage:** `ktd bump [bump_type]`
- **Arguments:**
  - `bump_type` (Optional, default `both`): `code`, `name`, or `both`.
- **What it does:** Auto-increments `versionCode` and `versionName` directly inside `app/build.gradle`.
- **Example:**
  ```bash
  ktd bump both
  ```

### CI/CD & Automation

#### `ci-init`
Initialize CI/CD pipeline configurations.
- **Usage:** `ktd ci-init [--provider <github|gitlab>]`
- **What it does:** Automatically generates standardized workflows (e.g., `.github/workflows/android.yml` or `.gitlab-ci.yml`) to instantly enable cloud building, testing, and artifact generation on every Git push.
- **Example:**
  ```bash
  ktd ci-init
  ```

### Environment Settings

#### `setup`
Run the Master Setup Wizard (See First-Time Setup).

#### `update-config`
Interactive configuration updater.
- **Usage:** `ktd update-config`
- **What it does:** Connects to official Gradle, Kotlin, and Google Maven APIs to fetch the absolute latest stable versions. It presents you with an interactive menu to update your global `ktroid` configuration, while strictly verifying any custom version inputs against live servers to prevent broken builds.

#### `config`
View current global configuration.
- **Usage:** `ktd config`
- **What it does:** Prints your current default Android ecosystem versions stored in `config.json`.

#### `check`
Verify the environment requirements.
- **Usage:** `ktd check`
- **What it does:** Checks `java -version`, `ANDROID_HOME`, `adb`, and `gradle` paths to ensure your system is ready for Android compilation.

#### `version`
Show CLI version.
- **Usage:** `ktd --version` or `ktd version`

## Configuration Reference

`ktroid` maintains a persistent global configuration in `config.json` (located in the package installation directory). This file dictates the default versions injected into newly created projects.

| Key | Description | Example Default |
|---|---|---|
| `java_version` | The JVM target and source compatibility level. | `17` |
| `agp_version` | Android Gradle Plugin (AGP) version. | `8.13.2` |
| `gradle_version` | Gradle distribution wrapper version. | `9.3.1` |
| `kotlin_version` | Kotlin compiler and standard library version. | `2.2.21` |
| `compile_sdk` | Android API level used to compile the app. | `35` |
| `min_sdk` | Minimum Android API level required to run the app. | `21` |
| `target_sdk` | Android API level the app is tested against. | `35` |
| `build_tools_version`| SDK Build-Tools version used by AGP. | `35.0.0` |

Use `ktd update-config` to safely modify these values.

## Project Structure

When you run `ktd create`, it generates a standard Gradle-based Android structure:

```text
MyApp/
├── app/
│   ├── build.gradle              # App-level build config
│   ├── proguard-rules.pro
│   └── src/
│       └── main/
│           ├── AndroidManifest.xml
│           ├── java/com/mycorp/app/
│           │   └── MainActivity.kt
│           └── res/              # Layouts, strings, colors, mipmaps
├── build.gradle                  # Root-level build config
├── gradle.properties             # Global Gradle JVM arguments
├── settings.gradle               # Project module definitions
├── gradlew                       # Unix Gradle wrapper script
└── gradlew.bat                   # Windows Gradle wrapper script
```

## How It Works

`ktroid` is a Python-based CLI wrapper. It does not replace the Android build system; it orchestrates it.
1. **Scaffolding:** Templates are generated dynamically in Python based on `config.json` values.
2. **Execution:** Commands like `ktd build` and `ktd run` act as intelligent wrappers around `gradlew` and `adb`. They manage permissions, parse configuration, filter complex logcat output, and auto-discover devices.
3. **Compatibility:** Because `ktroid` generates standard Gradle files and layouts, a project created in `ktroid` can be opened in Android Studio at any time with zero modifications.

## Comparison: ktroid vs Android Studio

| Feature | ktroid | Android Studio |
|---------|--------|----------------|
| **Resource Usage** | Extremely Low (Python process) | High (Heavy Java/IntelliJ GUI) |
| **Speed** | Instant CLI execution | Requires IDE indexing |
| **UI Design** | Requires coding XML/Compose | Drag-and-drop Layout Editor |
| **Automation/CI** | Built-in CLI commands | Requires bash scripting |
| **Profiling/Debugging** | ADB logcat wrappers | Visual Memory & CPU Profilers |
| **Vim/NeoVim friendly** | Yes (Use any editor) | No |

## Troubleshooting

- **`gradlew not found`**: Ensure you are running commands like `build`, `run`, or `test` from the root of your project directory (the folder containing `settings.gradle`).
- **`app/build.gradle not found`**: You might be missing the `app` module directory, or you are running dependency/permission commands in the wrong directory.
- **`sdkmanager not found`**: Your `ANDROID_HOME` or PATH is not set correctly. Run `ktd setup` to automatically fix paths and download command-line tools.
- **`No connected devices found`**: Ensure your Android device has Developer Options and USB Debugging enabled, or start an emulator using `ktd emulator start <name>`.
- **`Build failed`**: Run `./gradlew assembleDebug --stacktrace` manually to see raw Gradle errors.
